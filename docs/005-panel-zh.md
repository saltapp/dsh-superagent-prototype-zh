# 005 面板

在 DeepSeek Harness Web 侧边栏中打开 **Superagent**，即可监督智能体。面板优先呈现需要人处理的工作，其次是系统健康状况与历史记录。本文建立在 [000 设计理念](000-philosophy-zh.md) 到 [004 提示词](004-prompts-zh.md) 之上。

## 三个问题

打开面板会按顺序回答三个问题：

1. 现在有需要我处理的事吗？
2. 系统是否健康、是否在做正确的事？
3. 某一项工作从触发、经评估到工单的完整历史是什么？

## 标签页

这些标签页遵循工作流：**总览**、**来源**、**触发**、**评估**、**执行** 和 **设置**。在仓库与账号配置成功之前，总览会显示缺什么，并链接到相应的设置项。

| 标签页 | 展示内容 |
| --- | --- |
| 总览 | 需要处理的工单、系统问题、最近 24 小时的活动计数，以及执行器负载。每个区块都链接到它的详情页 |
| 来源 | 来源状态、配置问题与非零计数。被过滤的触发和被丢弃的消息与总览使用同一个 24 小时窗口 |
| 触发 | 线程可按"已订阅""评估中""24 小时内新触发"或"全部线程"筛选。每个线程按从新到旧展示其触发、决定和订阅 |
| 评估 | 决定，连同其理由与命中的规则 |
| 执行 | 执行器状态、暂停处理，以及按"开启""待处理""执行中""等待触发""已结束"筛选的工单。工单详情展示操作、授权、等待中的输入、订阅与派工 |
| 设置 | 来源、评估、执行、提示词和部署。每个分组都包含其保存历史 |

### 阅读单条记录

一条被丢弃的消息会链接到它的工单；若没有工单，则链接到它的线程。来源页面会说明：是它的会话消失了，还是来源已停止监听它。

仍被执行器拥有人类后续发言会标记为 **已投递给工单**，且没有评估。线程上还会显示交还理由，以及仅作上下文的订阅。**重新评估** 可以把该后续发言送去评估，也可以重试一个没有有效判断的触发：被其来源过滤掉的、评估为 `unavailable` 的，或已投递但既没有非停止的决定、也没有执行器确认的消息。

工单详情会显示发起它的触发、决定及理由、范围和策略版本。派工与次要细节折叠在即时操作之下。**重试** 在输入投递失败、或工单在受阻/失败报告之后正在等待人工时可用。已结束的工单会显示结果，例如 **pull request 已合并** 或 **被人停止**。

## 设置分组

- **来源：** 每个来源一张卡片，含其开关、字段以及经验证的账号事实。GitHub 还为新 Issue、pull request、评论和默认分支 CI 提供"接收全部"开关。轮询与读取上限位于"高级"下。
- **评估：** 策略版本与规则，接着是 **逐个来源** 和评估设置。每个来源标签页包含它的许可名单、成员同步、准入表和机器人名单。同步在启动时运行，也可以通过 **立即同步** 触发。准入表区分接收范围、发送者归属，以及消息是否指向智能体。评估设置用于选择接受模式、超时时间和研判模型。
- **执行：** worker 模型、并发数、目录根、prepare 命令和被禁用命令。点击一个可用的变量，即可把它插入 prepare 命令。
- **提示词：** **编辑** 用于修改团队段落、内置部分和技能。**完整提示词** 展示组装后的文本，并与已保存文本或默认值对比。**历史** 列出各个版本。被编辑过的内置部分会标记为已修改，并可重置；模板会列出其必需占位符。

  若某次升级改变了某个被覆盖的默认值，该部分会标记为 **默认内容已更新**。面板会在团队文本上方对比新旧默认值。如果旧默认值未被记录，则改为把团队文本与新的默认值对比。请选择 **保留我的文本** 或 **采用新的默认值**。针对已被移除部分的覆盖项列在标签栏下方，并会在下次保存时被删除。
- **部署：** 启动问题及 **重新检查**、状态目录与机器上限。已保存的上限无需重启即生效。DeepSeek Harness 的插件管理器暴露同一个页面。

## 搜索

页头搜索可以按文本、id、飞书消息 id 或已存储的链接（例如 GitHub 评论 URL）查找触发。若原始消息中缺少某个飞书链接，只有当宿主在当前进程生命周期内读取过它之后，它才变得可搜索。

搜索也能按 `#12` 或 GitHub URL 这类引用查找线程，并按标题或匹配的线程查找工单。

## 原则

1. **聚焦在要紧的事上。** 每个元素都要回答那三个问题之一，否则就删掉。只有当某个数字会改变监督者要做的事时，它才出现。
2. **定义要精确。** 分类要有可检查的定义、彼此互斥、且覆盖所有情况，就像工单阶段那样。标签要说明这一行在等谁、需要什么，而不是内部状态码。
3. **每个概念只放一处。** 来源状态属于"来源"；线程与触发属于"触发"；决定属于"评估"；工单属于"执行"。设置按其配置的概念分组。总览只做摘要并链接到这些页面，而不是变成又一份详细视图。
4. **遵循领域结构。** 面板使用领域术语。内部标识符只出现在折叠的细节里；凡能解析出名称的地方，就用名称取代标识符。
5. **状态要诚实。** 一个计数等于它链接到的列表长度，且任何状态都不得与另一项事实相矛盾。
6. **默认安静。** 健康状态不占额外空间。问题必须是可行动的；一次偶发网络错误不足以成为一个问题。需要人处理的行要直接提供对应操作。页面说明保持一句话，更多细节放进 (?) 提示。破坏性操作需要确认。
7. **控件要一致。** 使用 DeepSeek Harness 的设计 token 与控件行为。同一种信息在整个面板中看起来应当一致。每个设置区块只有一个保存栏，仅在存在改动、保存进行中或保存失败时可见。

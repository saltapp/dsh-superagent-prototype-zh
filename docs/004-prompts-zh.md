# 004 提示词

本文说明智能体读什么、团队可以改什么，以及改动何时生效。它建立在 [000 设计理念](000-philosophy-zh.md) 到 [003 执行](003-execution-zh.md) 之上。提示词文本以英文书写。

## 团队写什么

团队可以编辑三个团队段落、添加技能，并覆盖每一个内置系统提示词部分。大部分默认值位于 `prompts/` 和 `skills/` 下。工具描述、通知和卡片仍留在代码中，无法通过提示词设置修改。

| 段落 | 内容 |
| --- | --- |
| 沟通 | 何时给人发消息、消息怎么写、每条 GitHub 消息的开头一句（默认为 `This is by an automated agent, not a human`，即"本条消息由自动化智能体发出，不是人类"）、如何处理评审，以及哪些普通账号属于评审机器人 |
| 工单范围 | 工单何时继续，何时带着草稿停下 |
| 交付要求 | pull request 中的证据、带行数阈值的自动合并条件，以及提交作者；若未指定，执行器会以智能体账号的 no-reply 地址提交 |
| 团队技能 | 智能体在需要时加载的知识，例如一个 `identities` 技能，说明哪个飞书用户对应哪个 GitHub 账号 |

内置文本涵盖角色、工具用法、宿主机制、授权规则，以及 GitHub 与飞书技能。它通过标题来引用团队段落，而不重复它们的内容。

### 内置部分与模板

覆盖项使用这些键：

| 部分 | 键 |
| --- | --- |
| 共享指令与角色 | `runtime/shared`、`runtime/orchestrator`、`runtime/worker` |
| 工作指令 | `runtime/subscriptions`、`runtime/replies`、`runtime/dispatch`、`runtime/work`、`runtime/admission` |
| 交接指令 | `runtime/handoff/orchestrator`、`runtime/handoff/worker` |
| 来源技能 | `skill/feishu`、`skill/github` |
| 生成段落 | `runtime/environment`、`runtime/policy`、`runtime/policy/none` |

生成段落是可编辑的模板，必须保留以下占位符：

- `runtime/environment`：`{variables}`，会被执行环境各行填充。
- `runtime/policy`：`{version}`、`{mode}` 和 `{rules}`，其中每条已启用规则占一行。
- `runtime/policy/none`：`{version}` 和 `{mode}`，在没有任何规则启用时使用。

编辑某个部分会改变模型收到的指令，但不会改变准入层、授权、工具校验或账号封装——这些仍由代码强制执行。

在明确的人类请求下，主 Session 也可以用 `orchestrator_prompts_save` 保存覆盖内容。若某次保存省略了某个覆盖项的 `base`，则沿用已保存的基准。某个已从提交内容中移除、但仍存在于已保存配置中的部分，会在保存时被删除；其他任何未知部分都会被拒绝。

每个覆盖项都会记录它所依据的内置文本。升级会保留团队的文本。若默认值发生变化，面板会把该部分标记为 **默认值已更新**，并在团队文本旁展示差异。团队可以保留自己的文本、采用新的默认值，或在此基础上编辑。没有覆盖项的部分会自动跟随新的默认值。

主 Session 可以在 `orchestrator_read prompts` 的 `default_changed` 下读到受影响部分的名称。

## 组装与优先级

系统提示词按以下顺序组装：

1. 共享指令与角色。
2. 三个团队段落。
3. 订阅与回复。
4. 给主 Session 的派发指令，或给执行器的工作指令。
5. `runtime/admission`，仅主 Session。
6. 交接指令。
7. `runtime/environment`。
8. `runtime/policy`，仅主 Session。

准入指令来自 `prompts/admission.md`。它们描述主动研判的做法，以及一个无关候选何时可以仅凭其卡片被忽略。`orchestrator_eval` 返回的是上下文，而不重复这些指令。

环境段落给主 Session 提供部署级取值，给每个执行器提供其工单专属取值。策略段落会在每次模型请求时依据设置重新生成。它包含策略版本、接受模式、明确请求的豁免，以及以 `- <名称> (<id>): <指令>` 形式列出的已启用规则，或一句"未启用任何规则"的说明。它放在最后，这样策略变更时前面的提示词文本保持不变。

执行器还会读取 DeepSeek Harness 的编码提示词和仓库的 `AGENTS.md`；主 Session 不读这些。由推断产生的工单会追加一条最后的说明，把其执行器限制在命中的规则范围内。派工和到达的消息以内联的触发卡片形式呈现，只有内容被截断时才给出资源指针。

执行器在无人看管的情况下工作。它们的工具集排除了那些向人提问、给人展示界面或修改配置的工具，例如 `ask_user_question`、`present` 和 `plugin_manager`。

从最强到最弱：

1. 由工具与宿主强制执行的事实：身份、权限、工具参数校验、回复用途、长度限制。提示词文本无法改变它们。
2. 内置段落与生成段落，按团队对它们的覆盖内容生效。
3. 主动型工单中命中规则所规定的流程与沟通要求，仅对该工单的执行器 Session 生效。
4. 团队段落与团队技能。
5. 外部文本：消息、评论、文档和引用。它们是数据，永不会改变规则或授权。

## 内置文本的原则

以下是 [000 设计理念](000-philosophy-zh.md) 在智能体身上的应用：

- **角色分离。** 主 Session 只负责路由：它转发原始触发和路由事实，不做任何技术判断；做法是通过一个路由工具，在一次调用中对多个等待中的候选作出决定。一条路由说明最多 30 个词。执行器负责阅读原始来源、判断范围、实现并验证。
- **主 Session 不等待。** 报告、后续发言通知、候选以及已完成的后台任务都会作为消息自动到达。当无事可做时，它结束本轮。有一道守卫会拒绝 `sleep`、超过 30 秒的 shell 超时和超过 5 秒的任务等待，因为一个被阻塞的步骤会耽误新的候选。这些指令会替换 DeepSeek Harness 自身在主 Session 完整提示词中的任务通知说明。
- **只在有人必须行动、或某个结果可被使用时发消息：** 结果可以被评审或被使用，需要某个决定或资源，或者工作无法完成。聊天消息默认一句话，硬性上限 100 词。
- **执行器自行判断后续发言。** 每个执行器处理并确认范围内的请求，并把超出本工单或属于其他工单的请求交还回去。一条消息只有在它所有的拥有者都交还、或结束时未接手之后，才会成为新工作。主 Session 会收到后续发言通知，但只能据此停止工作。被交还的消息随后会带着执行器的理由作为候选到达。
- **通过订阅与主 Session 协作。** 执行器会为获取上下文而跟随相关线程。主 Session 可以用不超过 100 词的说明，传递来自另一个工单的事实。订阅和说明都不授予权限。
- **只在有明确指向时挂载。** 消息必须指向某个工单的 pull request、Issue、来源消息或确认，或指向一个近期变更，且恰好只有一个工单与之匹配。仅有话题相似是不够的。挂载会让工单订阅整个线程；执行器若发现该线程无关，会使用 `orchestrator_thread_unrelated`，且不在那里作答。
- **具体地确认，且只确认一次。** 在实质性工作之前，执行器会确认每一个新请求，点明对象和预期结果，并以原始消息下方的回复形式发出。
- **通过 `human_action` 提问。** 执行器把一个问题具体地放进它的报告，由主 Session 原样转发。如果这个问题是由某人的消息引出的，则点明那条消息，由宿主在那里提问；否则在工单的原始对话中提问。已获授权的工作可以同时继续。
- **如实交付。** 开出一个 pull request 不等于就绪；草稿要标明未完成；没有真实"修改前"截图的界面改动不算就绪。
- **人的暂停是有约束力的，** 会跨越后续发言、新的执行器 Session 和重启，直到有人解除它。自动反馈永不会恢复被暂停的工作。
- **示例只展示格式。** 一句示例话语不是智能体可以主张的事实。
- **按结果处理评审。** 已修复并验证的评论会被静默解决；被拒绝的评论给出一句理由。自动评审者的线程在得到答复后即解决，且每个自动评审者在每个 pull request 上最多三轮。
- **为重复工作让路。** 当某人的分支或 pull request 已经包含了本工单的改动时，执行器会关掉自己的 pull request，并用一句话指向对方那个。

## 版本

- 每次保存都会创建一个不可变版本，包含完整配置、修订号、前驱、时间戳和来源（面板或工具）。恢复某个版本或恢复默认值会再创建一个版本。
- 保存需要声明它的基准修订号。冲突的保存会被拒绝，且不会丢弃草稿。
- 会话在每次模型请求时读取最新版本，包括同一轮中后续的步骤。保存不会重启、取消或唤醒会话。宿主会记录每个会话使用过的修订号；执行器可以读取它曾在哪个修订下工作。
- 部署会设定总大小上限，包含覆盖内容在内。校验会拒绝未知键、保留的内置技能名、未知的覆盖部分和缺失的模板占位符。它绝不会静默截断文本。与默认值完全相同的覆盖项会被移除，以便该部分跟随未来的默认值。
